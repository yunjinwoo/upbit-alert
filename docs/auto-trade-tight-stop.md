# 짧은 손절 · 긴 수익 (tight stop)

> 상태: ✅ 구현 완료 · **기본 꺼짐** (2026-09-21)
> 코드: `app/core/trade_strategy.py`의 `_evaluate_exit_tight_stop()` · 설정은 `/auto-trade` 화면의
> "⚙️ 매매 설정" 카드 > **짧은 손절 · 긴 수익**

## 왜 만들었나

"손절은 짧게, 수익은 길게"를 기존 설정으로는 만들 수 없었다. 원인은 두 가지다.

1. **수익이 짧게 잘린다** — 익절(`take_profit_pct`, 기본 +10%)이 추세와 무관하게 전량 매도한다.
   30%까지 갈 종목도 10%에서 끝난다.
2. **손절이 길게 늘어진다** — 트레일링 손절 조건이 충족돼도 물타기 횟수(`dca_max_count`, 기본 2회)를
   다 쓰기 전에는 매도가 나가지 않고 평단 대비 -10%마다 추가매수한다. 손실 종목에 원금이 더 들어간다.

손절 기준(`stop_loss_pct`)을 그냥 줄이면 되지 않느냐 하면, 그 값 하나가 **손실을 끊는 폭**과
**수익을 지키는 폭**을 겸하고 있어서 안 된다. 3%로 줄이면 +20%까지 오르던 종목도 3% 눌릴 때마다
털리고, 8%로 넓히면 진입 직후의 손실도 8%까지 열어주게 된다. 그래서 **두 폭을 분리**했다.

## 규칙

포지션이 두 구간 중 하나에 있다고 보고, 구간마다 다른 손절선을 쓴다. 구간을 가르는 기준은
**고점 수익률**(보유 중 최고가 `peak_price` 기준의 평단 대비 수익률)이다.

| 구간 | 조건 | 손절선 | 표시 |
|---|---|---|---|
| 전환 전 | 고점 수익률 < `tight_stop_arm_pct` | 평단 × (1 - `tight_stop_initial_pct`) | 🟡 짧은 손절 구간 |
| 전환 후 | 고점 수익률 ≥ `tight_stop_arm_pct` | **max**(고점 × (1 - `tight_stop_trail_pct`), **평단**) | 🟢 트레일링 구간 |

기본값은 `-2% / +5% / -8%`다. 예를 들어 평단 100원이면,

- 98원까지 내려오면 즉시 매도한다(-2%). 손실을 여기서 끊는다.
- 105원을 한 번이라도 찍으면 트레일링 구간으로 넘어간다. 그 뒤로는 고점에서 8% 밀릴 때까지 들고 간다 —
  고점이 120원이면 110.4원, 150원이면 138원이 손절선이고, 고점이 올라갈수록 같이 올라간다.
- 단 **본전 아래로는 손절선을 내리지 않는다**. 고점이 106원일 때 트레일링 손절선은 97.5원이지만,
  한 번 +5%까지 벌어둔 포지션을 다시 손실로 되돌려보내면 짧은 손절을 둔 의미가 없어서 이 구간의
  손절선은 평단(100원)이 된다. 고점이 약 108.7원을 넘어서야 트레일링 손절선이 평단 위로 올라온다.

### 같이 바뀌는 것

- **물타기를 하지 않는다.** 손실 종목에 원금을 더 넣는 건 "짧은 손절"과 정반대라, 같이 두면 손절이
  다시 늘어진다. 표의 물타기 칸도 "미사용"으로 바뀐다.
- **되돌림 익절(`trailing_tp_*`)은 무시한다.** "3~4% 갔다가 2%로 내려오면 익절"은 수익을 3%에서 끊는
  규칙이라 이 모드와 방향이 반대다. 두 설정이 동시에 켜져 있어도 이 모드가 이긴다.
- **연속 확인(`stop_loss_confirm_cycles`)을 기다리지 않는다.** 짧게 끊는 게 목적인데 몇 사이클을 더
  기다리면 그만큼 손실이 깊어진다.
- **익절과 RSI 과매수 매도는 그대로 앞단에 남는다.** 그래서 수익을 길게 끌고 가려면 익절 기준을
  충분히 높게(예: 30%) 두거나 사실상 꺼야 한다 — 안 그러면 +10%에서 여전히 잘린다.
- **회복형 분할 물타기가 켜져 있으면 그쪽이 우선한다**(`docs/auto-trade-recovery-dca.md`). 두 모드는
  정반대 성격이라 같이 켤 이유가 없다.

## 설정

| 키 | 기본값 | 의미 |
|---|---|---|
| `tight_stop_enabled` | `false` | 모드 on/off |
| `tight_stop_initial_pct` | `2.0` | 전환 전 손절 — 평단 대비 하락률(%) |
| `tight_stop_arm_pct` | `5.0` | 트레일링 전환 — 고점 수익률(%) |
| `tight_stop_trail_pct` | `8.0` | 전환 후 허용 하락 — 고점 대비(%) |

화면(`/auto-trade` > ⚙️ 매매 설정)에서 저장하면 `trade_strategy_settings` 테이블에 브로커별로 들어가고,
실행 중인 매매 프로세스가 **재시작 없이 다음 사이클부터** 새 값을 쓴다. 켜져 있으면 실거래 표 위에
한 줄 요약이 뜨므로 카드를 펼치지 않아도 지금 어떤 규칙으로 파는지 보인다.
API로는 `POST /api/auto-trade/settings`(토스는 `/api/toss-trade/settings`)에 위 네 키만 보내면 된다.

## 백테스트로 먼저 확인하기

이 모드는 승률이 떨어지고(짧게 자주 끊기므로) 손익비가 올라가는(이익 한 건이 크므로) 쪽이라,
합이 맞는지는 돌려봐야 안다. `docs/backtest.md`의 도구에 옵션이 붙어 있다.

```bash
python backtest.py run --compare                                       # 지금 설정(기준선)
python backtest.py run --selection gainers --tight-stop --take-profit 30
python backtest.py run --selection gainers --tight-stop --tight-initial 3 --tight-trail 12 --take-profit 30
```

성과 화면(`/auto-trade/performance`)과 백테스트 리포트의 청산사유는 이 모드의 것을 따로 센다 —
`tight_stop_loss`(짧게 끊은 손실) / `tight_trail_exit`(트레일링으로 확정한 이익) /
`tight_breakeven_exit`(본전에서 막은 건). 세 건수와 평균 손익을 보면 "손실은 작게, 이익은 크게"가
실제로 도는지 바로 보인다.

## 한계 / 아직 안 한 것

- **손절선이 사이클 주기로만 확인된다.** 루프 주기(기본 300초) 사이에 -2%를 지나쳐 훅 빠지면 그보다
  깊은 값에 체결된다. 지정가 스톱 주문을 거래소에 걸어두는 방식은 아직 없다.
- **단계별 래칫(+3%면 본전, +6%면 +3%로 손절선 올리기)은 넣지 않았다.** 전환 후 "본전 아래로 안 내림"이
  그 1단계에 해당한다. 더 잘게 나눌지는 백테스트 결과를 보고 정한다.
- **변동성(ATR) 기반 폭 조절도 안 했다.** 지금은 종목과 무관하게 같은 %를 쓴다.

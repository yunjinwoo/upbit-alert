# 2단계: 모멘텀 점수(거래량 배수 + 등락률 조합) 산출 함수

- 상태: 완료
- 날짜: 2026-07-10
- 관련 파일: `app/utils/db_manager.py`

## 작업 내용
1번(거래량 배수)에서 만든 데이터에 당일 등락률(`change_rate`)을 조합해 0~30점 만점의 모멘텀 점수를 계산.

### 점수표 (`_score_momentum(ratio, change_rate)`)

| 조건 | 점수 |
|---|---|
| 배수 ≥ 3 이고 등락률 > 3% | 30 |
| 배수 ≥ 3 이고 등락률 > 0% | 25 |
| 배수 ≥ 2 이고 등락률 > 1% | 20 |
| 배수 ≥ 2 이고 등락률 > 0% | 15 |
| 배수 ≥ 1.5 이고 등락률 > 0% | 10 |
| 배수 ≥ 2 이고 등락률 < 0% (거래량은 터졌는데 하락 — 이탈/분산 신호) | 5 |
| 그 외 (배수 낮음 또는 하락+거래량 부족) | 0 |

거래량 급증과 가격 상승이 동시에 나타날수록 고득점, 거래량만 늘고 가격이 빠지면 낮은 점수로 처리 — 기존 기획안의 "거래량 증가 + 가격 상승 동시 발생 우대 / 가격 오르는데 거래량 줄면 감점" 아이디어를 단순화해서 반영.

### 신규 함수
- `get_momentum_score(code, avg_days=20)` — 종목 하나의 모멘텀 점수 계산. 반환: `{code, date, ratio, change_rate, score, days_used}`
- `get_momentum_score_batch(date=None, avg_days=20, fid_input_iscd="combined")` — 전 종목 일괄 계산, 점수 내림차순 정렬. 1번에서 만든 `get_volume_ratio_batch()`를 재사용하고 `change_rate`만 조인해서 계산.

## 검증
테스트 종목코드로 가짜 데이터(과거 5일 평균 거래량 100,000 + 당일 거래량 350,000(3.5배) + 당일 등락률 4.2%)를 넣고:
- `get_momentum_score('TESTCODE')` → `{ratio: 3.5, change_rate: 4.2, score: 30}` 정확히 계산됨
- 경계값 케이스 5개(`_score_momentum` 직접 호출)로 점수표 각 구간 확인 — 모두 기대값과 일치
- `get_momentum_score_batch()`에서도 동일 종목이 `score: 30`으로 정확히 포함됨을 확인
- 검증 후 테스트 데이터 삭제

## 주의할 점
- 1번과 마찬가지로 실제 거래량 데이터가 아직 0일치 누적된 상태라, 지금 시점에 이 함수를 실제 종목에 돌리면 전부 `ratio: 0.0, score: 0`으로 나옴 — 데이터 누적 현황은 `/volume-ratio` 페이지 배너에서 확인 가능.
- 화면(UI) 반영은 아직 하지 않음 — 필요하면 `/volume-ratio` 페이지에 등락률/점수 컬럼을 추가하는 방식으로 확장 가능.

# 7단계: 종합 Signal Score 통합 + A/B/C 등급 분기

- 상태: 완료
- 날짜: 2026-07-10
- 관련 파일: `app/utils/db_manager.py`

## 작업 내용
2~6번에서 만든 점수 함수를 모두 합산해 종합 점수와 알림 등급을 산출하고, 결과를 DB에 저장하는 로직 추가.

```
종합점수 = 모멘텀(0~30) + 수급(-15~30) + 랭킹안정성(0~15) + 시장환경(0~15) + 리스크패널티(-20~0)
```

### 등급 기준
| 등급 | 점수 | 의미(기획 원안) |
|---|---|---|
| A | 80점 이상 | Slack 즉시 알림 |
| B | 65~79점 | 대시보드 상단 노출 |
| C | 50~64점 | 저장만, 알림 생략 |
| 제외 | 50점 미만 | — |

(8번에서 실제 Slack/대시보드 배선을 만들기 전까지는 등급 산출만 하고 실제 알림 발송은 아직 연결 안 됨)

### 신규 테이블
- `signal_score_daily` — 날짜별 종목별 각 구성 점수 + 총점 + 등급 저장 (`UNIQUE(date, code)`)

### 신규 함수
- `_grade_for_score(total)` — 점수 → 등급 매핑
- `get_signal_score(code, fid_input_iscd="combined")` — 종목 하나의 종합 점수/등급. 2~6번 함수를 그대로 호출해서 합산. `detail`에 각 구성 점수의 원본 결과를 그대로 포함(왜 이 점수가 나왔는지 추적 가능)
- `get_signal_score_batch(date=None, fid_input_iscd="combined", save=False)` — 전 종목 일괄 계산, 총점 내림차순. `save=True`면 DB 저장까지 수행
- `save_signal_score_daily(rows)` — 배치 결과를 `signal_score_daily`에 upsert
- `get_signal_score_history(date=None, grade=None, limit=100)` — 저장된 결과 조회 (날짜/등급 필터)

## 검증 (실제 데이터로 확인, 코스닥 30종목)
`get_signal_score_batch(fid_input_iscd='1001', save=True)`로 실행 → 30건 저장 확인, `get_signal_score_history()`로 재조회 확인.

**결과 관찰**: 현재 A/B등급이 하나도 없고 전부 C 이하로 나옴. 원인은 명확함 — 모멘텀 점수(최대 30점)가 거래량 배수 데이터 미누적으로 전종목 0점 처리되고 있어서, 이론상 최대 총점이 30(수급)+15(랭킹)+10(시장)=55점으로 제한됨. **이는 버그가 아니라 1번(거래량 배수) 데이터가 아직 쌓이지 않은 상태를 정확히 반영한 결과**임 — 거래량 데이터가 쌓이기 시작하면 모멘텀 점수가 살아나면서 A/B등급 종목이 정상적으로 나올 것으로 예상.

- 최고 점수: 클래시스(214150)·디앤디파마텍(347850) 55점 (C등급) — 수급 동반매수(30) + 랭킹 상승(15) + 시장 양호(10)
- 최저 점수: 보로노이(310210)·HPSP(403870) -10점 (제외) — 동반 순매도(-15) + 리스크 패널티(-15)까지 겹침
- 주성엔지니어링(036930): -5점 (제외) — 동반 순매도(-15) + 리스크 패널티(-15)지만 랭킹안정성(15)이 상쇄

숫자 흐름이 이치에 맞게 나옴(수급 좋고 랭킹 오르는 종목이 상위, 동반 매도+과열 위험 겹친 종목이 최하위).

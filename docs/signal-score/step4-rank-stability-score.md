# 4단계: 시총/랭킹 안정성 점수 산출 함수

- 상태: 완료
- 날짜: 2026-07-10
- 관련 파일: `app/utils/db_manager.py`
- 참고: 계획표 순서상 3번(수급 점수)보다 먼저 진행됨 — 진행 순서 착오. 3번은 이어서 진행 예정.

## 작업 내용
시가총액 순위(`stock_market_cap_daily.rank`)를 이용해 0~15점 만점의 랭킹 안정성 점수를 계산.

### 점수 구성
- 최신 랭킹이 상위 100위 이내 → **+10점** (소형주/작전주 리스크 대비 신뢰도)
- 최근 N영업일(기본 5일) 전 대비 랭킹이 상승(순위 숫자가 작아짐) → **+5점**

### 신규 함수
- `get_rank_stability_score(code, trend_days=5, fid_input_iscd="combined")` — 종목 하나 계산. 반환: `{code, date, rank, rank_before, rank_change, score}`
- `get_rank_stability_score_batch(date=None, trend_days=5, fid_input_iscd="combined")` — 전 종목 일괄 계산, 점수 내림차순(동점이면 랭킹 오름차순) 정렬

## 검증 (실제 데이터로 확인)
1번/2번(거래량 배수·모멘텀)과 달리 시총 랭킹 이력은 **이미 1개월치(2026-06-11 ~ 2026-07-09) 쌓여있어서 실제 종목으로 바로 검증 가능했음**.

- 삼성전자(005930, 항상 랭킹 1위): `rank_change: 0` → 보너스 없이 기본 10점만 부여됨 (정상 동작)
- HPSP(403870, 랭킹 변동 큰 종목): 21위 → 20위로 상승 → `score: 15`
- 코스닥(1001) 2026-07-09 기준 배치 계산 상위 종목 예시:
  - 레인보우로보틱스(277810): 5위→4위, score 15
  - HLB(028300): 7위→6위, score 15
  - 클래시스(214150): 30위→19위 (11계단 상승), score 15

## 발견한 이슈 (내 작업과 무관, 기존 데이터 이슈)
`get_rank_stability_score_batch(fid_input_iscd='combined')`로 조회했을 때 삼성전자 등 코스피 종목이 최신일(2026-07-09)에 안 나와서 확인해보니, **2026-07-09에는 코스닥(1001)만 수집되고 코스피(0001) 수집이 누락**된 상태였음.
```
2026-07-08: 0001(코스피) 30건, 1001(코스닥) 30건
2026-07-09: 1001(코스닥) 30건만 존재, 0001 없음
```
원인은 별도 조사 필요 (`stock_monitor.py`의 일별 수집 스케줄 또는 KIS API 응답 문제 추정). 이번 단계 작업엔 영향 없지만, 5번(시장/업종 환경 점수)이나 종합 스코어 계산에서 특정 날짜에 코스피 데이터가 누락되면 오탐이 생길 수 있어 별도로 확인이 필요함.

# 6단계: 리스크 패널티 함수

- 상태: 완료
- 날짜: 2026-07-10
- 관련 파일: `app/utils/db_manager.py`

## 작업 내용
과열·이탈 신호를 감지해 -20~0점의 패널티를 산출. 원래 기획안의 "윗꼬리 과다", "갭상승 후 하락" 조건은 고가/저가/시가 데이터가 DB에 없어서(현재 `stock_market_cap_daily`는 현재가만 저장) 제외하고, 실제로 계산 가능한 조건만 반영함.

### 패널티 조건
| 조건 | 점수 |
|---|---|
| 최근 5영업일 누적 상승률 30% 이상 (과열) | -15 |
| 당일 거래량 배수 2배 이상 + 등락률 음수 (거래량 터졌는데 하락 = 이탈 신호) | -10 |
| 외국인·기관 3일 동반 순매도 | -15 |

합산 후 **-20점 하한**(여러 조건이 겹쳐도 -20점 이하로는 안 내려감).

### 신규 함수
- `_get_cumulative_return(code, days=5, fid_input_iscd="combined")` — 최근 N영업일 누적 상승률(%) 계산 (내부 헬퍼)
- `get_risk_penalty(code, fid_input_iscd="combined")` — 종목 하나의 리스크 패널티. 반환: `{code, date, cum_return_5d, ratio, change_rate, supply_demand_score, penalties(사유 목록), score}`
- `get_risk_penalty_batch(date=None, fid_input_iscd="combined")` — 전 종목 일괄 계산, 점수 오름차순(가장 위험한 종목이 먼저)

기존 3번(수급)·2번(모멘텀) 함수를 그대로 재사용해서 계산 — 새로 만든 것은 5일 누적 수익률 계산과 패널티 합산 로직뿐.

## 검증 (실제 데이터로 확인)
- 주성엔지니어링(036930), 보로노이(310210), HPSP(403870) — 이미 3번에서 확인한 "외국인·기관 동반 순매도" 종목들이 여기서도 정확히 `score: -15`로 나옴
- 삼천당제약(000250, 수급 양호) → 패널티 없음, `score: 0`

## 알려진 한계
- **거래량 기반 패널티는 아직 검증 불가**: 1번(거래량 배수) 데이터가 여전히 0일치라(진행 중인 별도 이슈), "거래량 급증+하락" 조건이 실제로 발동하는 걸 본 적은 없음. 데이터가 쌓이면 자동으로 반영됨.
- **당일 대폭락은 놓칠 수 있음**: 배치 테스트 중 HLB(028300)가 당일 -29.89% 급락했는데도 수급이 동반 순매수(+30)라 패널티 0점으로 나온 사례를 발견함 — 거래량 배수 데이터가 없어서 "거래량 급증+하락" 조건이 못 잡은 것. 원래 기획에 없던 "당일 단독 급락" 조건은 이번 범위에 추가하지 않음(과도한 확장 방지) — 필요하면 별도로 논의.
- 윗꼬리/갭상승 조건은 고가·저가·시가 데이터 자체가 없어 아예 구현 안 함.
